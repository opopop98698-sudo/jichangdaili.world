## 2. 免费节点的五步安全接入标准

如果你确实需要使用公共免费节点完成应急任务（例如拉取 GitHub 仓库或更新本地配置），请严格遵守以下防泄露五步法：

```
[步骤 1: 审查链接纯净度]
检查订阅 URL 或节点参数，确认其是否指向合法的域名或 IP，排查是否存在重定向至钓鱼网站的恶意参数。

[步骤 2: 拒绝安装未知证书]
若任何免费软件或节点要求你导入“根证书 (Root CA)”或“SSL 证书”，必须立刻放弃！这是中间人攻击 (MITM) 的核心特征。

[步骤 3: 严格开启浏览器 HTTPS 强制]
在 Chrome 或 Edge 浏览器设置中开启“始终使用安全连接 (HTTPS-First)”，确保传输层端到端加密不被劫持。

[步骤 4: 规避真实内网暴露]
在客户端分流规则中，务必将本地私有网段（192.168.0.0/16, 10.0.0.0/8, 127.0.0.1）置于 DIRECT 直连策略，防止内网设备被嗅探。

[步骤 5: 任务完成后彻底清除缓存]
应急任务结束后，在客户端中删除该免费订阅与节点记录，并清空本地 DNS 与浏览器缓存。
```

## 3. 为什么免费节点经常大面积“变红超时”？

许多初学者常困惑为什么早上还能用的免费节点，下午全部提示 `Timeout` 或 `Connection Refused`。其背后的技术原理主要有三个方面：

1. **IP 阻断与主动探测**：公开发布在 GitHub 或社交平台的节点 IP 和端口，会被自动化防火墙探测系统在数小时内快速捕获并施加 TCP 阻断或重置。
2. **带宽配额耗尽**：公共 VPS 服务器通常有固定的月度出方向带宽（如 1TB/月）。一旦被爬虫收录进大型节点池，往往在几小时内就会跑满流量配额导致服务商自动关机。
3. **恶意滥用与运营商封禁**：由于免费节点缺乏身份认证，经常被脚本黑客用于发起大规模扫描、撞库或垃圾邮件发送，触发机房的自动化安全封禁机制。

## 4. 商业试用套餐的防坑与测试技巧

很多商业服务商会提供 1 元试用或免费领取的 3 天测试体验。在试用期间，推荐重点测试以下三项指标：

- **节点池是否为独立隔离池**：检查试用套餐分配的节点列表，是否与付费主套餐属于同一组服务器，防止商家使用虚假优质节点引流后在付费套餐中降级。
- **晚高峰吞吐与丢包实测**：在 20:30 至 22:30 的骨干网拥塞时段执行连续的 `tcping`，记录丢包率是否超过 15%。
- **自动续费与解绑**：切勿在未明确取消自动续费前绑定高额度信用卡，优先使用免密代扣关闭的单次支付渠道。
